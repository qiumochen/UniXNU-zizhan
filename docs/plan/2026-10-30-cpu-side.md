# 合成器 CPU 端提速方案（2026-10-30）

现状：内核侧扫描输出约 3 ms/帧，GPU 平均忙 3–10%（sheng 调度器），滑动帧率仍 30–35 fps，帧间隔多在 25–50 ms，瓶颈在 CPU 端（backboardd / CoreAnimation / metal2vulkan 提交 / 呈现器）。本方案基于类似项目的一手资料（调研见对话；克隆在会话 scratchpad `research/`）。

## 阶段 A：定位（只改内核，每轮约 2.5 分钟）
- **A1 按刷新节拍分析帧间隔**：把帧间隔按 120 Hz 的 8.33 ms 整数倍分档，区分"渲染慢"和"多等了整拍"。参考 iola1999/hackios-redmi-k90-annibale `docs/analysis/2026-10-29-frame-budget.md` §6（97% 落在 1/2/3 拍上）。
- **A2 按进程/核/线程的 CPU 采样**：内核 1 kHz 采各核当前进程/线程/PC，统计 backboardd 各线程所在核与 CPU 占用；用户 PC 带 dyld 镜像表离线符号化。参考 UniXNU-sheng `package/BootProgress.c`（PS/CPU/PP/PK 行）、`BootUiTraceProbe.c`；ShueiTsuki/data-a-live 0222/0223/0225、`tools/prof.py`。

## 阶段 B：只改内核、别人验证过的提速
- **B1 界面线程上大核**：先降温条件下单测 cpu0 占位；再移植 sheng `patches/xnu/zzyf-sheng-amp.patch`（E/P 两簇 + Edge），取代空转占位。参考 sheng 19960fa（40→55 fps）、MaliMetal `docs/notes.zh-CN.md`（A55 11.4 ms vs A76 3.8 ms）。风险：data-a-live 0320（无 CLPC 时 Edge 默认偏好启动簇）、coreduetd 占超大核、sheng iPadOS27 分支的 WFI 全核睡死（改回 WFE）。
- **B2 交换节奏**：SwapWait 照原版 `swap_wait_gated` 实现（data-a-live 0218），试 `fb_queue=2`。

## 阶段 C：用户态快速迭代
`XNU_NATIVE_OFFLINE_GPU=1` 打开 `zzy-native-gpu-addon-mount.patch`；UniXNU `scripts/make-gpu-addon.py` 把插件打进启动 payload，内核写到 Data 卷 `/private/var/ngpu` 后只读 union 挂到 `/System/Library/Extensions`；`scripts/make-owner-trust-bundle.py` 生成信任缓存。目标：改插件也是 payload 一轮。

## 阶段 D：用户态改动（按 A 的结果挑）
- 命令缓冲时间线（含核号）：MaliMetal `mali-timeline`。
- 专用编码线程按批喂：AdrenoMetal（61→67 fps，显示线程占用 90%→34%）；scanout 线程 UI 优先级（c6d29ca）；设备查询缓存（31867dc）。
- padded Alias 免影子拷贝：data-a-live（uke 每帧约 67 MB 影子流量）。
- metal2vulkan 升级：44d97aa（去延迟重放线程）、ca8340b（提交合批）。

## 顺序
A1 → B1 → A2 → C → B2/D。
