## 日用目标与阶段边界

先交付内屏 Wi-Fi 场景：浏览网页、文字输入、设置、照片浏览、切换应用、充电和放置后继续使用；再补声音、外屏与折叠，最终推进蜂窝与完整手机场景。内屏 Wi-Fi 阶段仍需联合验收，不能凭各模块有启动日志就称为可日用。蜂窝阶段分别覆盖移动数据、通话、短信及待机可达性；数据会话成功不代表完整手机能力。

优先级按使用中断和依赖排序：启动/数据完整性与温控 → 锁屏恢复及待机 → 网络与常用应用 → 声音与折叠 → 手机能力。主屏首帧优化继续保留，但安排在基础稳定性之后。电池健康页转圈独立处理，优先让真实电源状态、温度和充电行为可用。

## 第二阶段：声音、外屏与便携使用

音频 AUDIO-01 先核对本机 SE15、CS35L41 身份、复位/IRQ、固件及调音输入，准备隔离的只读探针。随后按功放、ADSP 路由、原生播放、静音/停止及恢复分段实现；扬声器和麦克风采集分别建链。IO-01 保留音量实体键候选，待声音链具备条件再做联动，不把路由 ready 当作按键通过，也不把寄存器写入成功当作出声。

折叠 FOLD-01 依次为独立外屏 profile、60 Hz 出图、外触控、手动切屏、Hall 自动切屏，最后与锁屏/唤醒联动。内外屏各自保留控制器、亮度、DSC、触控坐标和所有权描述。真机首次出光及开合需要姿态采集和人眼观察；此前可做输入解析、配置生成和状态机准备，但不能越过缺失的固件交接证据执行初始化。

DISP-01 中的环境光、方向等传感器按实际输入接入，手动亮度继续作为已验证控制。蓝牙 BT-01 先做传输、供电、固件和原生栈接口调查，再分别实现发现/配对、HID 外设和音频；蓝牙音频不作为尚未具备的本机音频链的默认替代方案。

第二阶段的联合目标是能听、能输入、能在两块屏幕间继续原有任务，并在放置与拿起后恢复。自动亮度、动态刷新率与性能微调按各自依赖推进。

## 第三阶段：蜂窝、相机及完整手机能力

MODEM-01 从本机 modem transport、固件、EFS/NV 保护和 OS 接口调查开始，再分固件启动、SIM、注册、数据通路、移动数据、通话/短信与待机恢复。通话依赖音频和电源状态；各阶段保持独立停止条件，不以 Wi-Fi 或单次注册推断成功。

CAM-01 先盘点本机传感器、供电、时钟、ISP、固件、缓冲分配和原生相机接口，再选单摄预览、拍照和 Photos 保存的最小闭环，之后扩到录像与其他镜头。此项是新规划，尚无本轮实现或设备资格。

应用兼容性在选定真实日用应用清单后扩展。账号、商店、DRM、推送和后台可达性按实际依赖单独研究；不预先承诺兼容。动态壁纸、额外 GPU 场景、高刷普及与更多内存使用排在已选日用阻塞之后。

RELEASE-01 的上游模板接入继续保留，但当前发布器缺 Darwin24 profile/recipe 扩展点，等待其支持期间，BASE-01 用现有可用链路推进本地可复现性，不靠改 sibling checkout 替代设备适配。

## 候选积累和集中验收

1. 人工和长时场景验收暂存；源码审查、配置检查、受影响主机回归和必需构建随开发完成。硬件结果仍需真实设备证据。本文不触发安装、设备启动或后台长跑。
2. 每项候选保存任务 ID、源 SHA 与 dirty diff、输入和产物 hash、依赖、默认开关、安装需求、验收步骤及回退；私有路径与输入放本机 handoff。`TODO`/`IN_PROGRESS`/`HOST_VERIFIED` 如实登记，不把“已准备”升级为设备通过。
3. 各候选先从已验证基线隔离派生。依赖另一待验候选的变更明确标注，暂不合并为默认日用包；集中验收先单项、后依赖组合，失败能回到原基线并定位变量。
4. 集中验收分为按键/充电及应用批次、音频批次、外屏/折叠批次、睡眠/网络及热稳定性批次。每批执行前冻结输入、期限、样本/重复次数和数值阈值，分别保留失败与缺失证据。
5. 长稳按短轮 → 2 小时交互/网络 → 8 小时待机逐级设计，后两者是计划目标，尚未获本轮启动安排。自然 T1 要根据真实租约单独定窗口；不把 8 小时观察或主动 renew 自动算作自然 T1。
6. 联合日用资格需在同一个候选上成立：启动与数据持久性、真实交互和内容、锁屏恢复、网络、电源/温度，以及对应阶段的声音/折叠/蜂窝。设备基线推广前检查增量和回退，发布时跟踪该 SHA 的实际 CI。

当前第一批可积累的人工项是实体音量键，以及电池/充电页面的现状核对；健康页修复、外屏、声音与真睡眠仍有开发或前置缺口。验收后置不改变这些边界。
