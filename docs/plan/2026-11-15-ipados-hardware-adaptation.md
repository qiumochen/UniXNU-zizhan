# iPadOS 硬件适配计划（2026-11-15）

## 目标

把 Android 侧已观察到的传感器、GNSS、扬声器/麦克风和折叠状态，逐项接入 zizhan 的 iPadOS 运行时。Android 证据只用于确认硬件和行为线索；每个 iPadOS 功能必须有自己的原生数据路径和设备验收。天气页面显示、传感器枚举、音频路由或构建成功都不能单独证明功能完成。

## 当前依据与限制

- Android 已枚举 LSM6DSO 加速度计/陀螺仪、AK0991X 磁力计、前后 TCS3720 光线、接近、铰链角度和 `fold_status`；两次完整开合都记录到约 178° 至 4–7°时闭合位翻转。
- Android GNSS 权限和总开关已开，但此前 Weather 在锁屏时启动，没有活动请求、定位结果或卫星统计。硬件没有被证明故障，也没有有效 fix。
- 现有 iPadOS 内屏路径只覆盖 DSI0。外屏还需要 DSI1/PHY1、secondary L18 初始化、TE、SE19 触控及独立显示 owner；当前没有外屏或自动折叠切换资格。
- `PongAudio.cpp` 是 Pong 的 TFA9873/SE13 路径（GPIO48/49、地址 0x34/0x35），与 zizhan 的 CS35L41/SE15（GPIO56/57、地址 0x40/0x42）不同。不能靠改地址复用寄存器配置；`pong_audio=0` 保持。
- 初查 `ArmDTPlatform` 仅见 TSENS；随后在维护中的 FTS patch 找到本机 TLMM GPIO 电平读取布局，并核对保存的live DT。已据此完成默认关闭 GPIO62 观察器及主机资格，见[首批交付](../progress/2026-11-15-hall-observer.md)。IMU/磁力计/ALS、GNSS真实输入链仍需适配。
- 可用的 XNU `IOInterruptController` 接口定义中断注册、类型、启停和分发，没有 GPIO 电平读取方法。平台专家发布设备树 nub 也不表示 GPIO 控制器已匹配或拥有该引脚。
- `PongAudio.cpp` 初始化时会配置 SE13/GPIO48/49 并操作 TFA9873 复位脚，不能把现有启动路径直接用于 CS35L41 的只读探针。需先抽出并验证 zizhan 专属 SE15 资源所有权，再允许访问芯片。
- 设备仓库代码索引目前不可用，本计划依据定向源码检索、`porting.toml` 和当前公开台账制定；实现时继续检查覆盖和真实源码。

## 工作顺序

### 0. 接续前置（主机只读）

目标：确认真实起点，避免把准备态、旧候选和已安装状态混为一谈。

- 记录当前 `main` HEAD、完整 dirty 状态和涉及文件；保留现有未提交修改，不清理或重置。
- 复核 22H374/XNU、DarwinBoot24、UI/helper 和回退输入的实际身份；检查进程、挂载、设备 owner 后才考虑设备轮次。
- 从设备专属 DT/Android 只读记录确认 GPIO62 Hall、传感器总线/IRQ、GNSS 资源、SE15 时钟/复位/IRQ、DSI1 和 SE19；未由本机 live 输入确认的属性标成待核。

验收：一份主机侧资源/接口清单，带来源、确认级别和缺失项；没有设备写入。

### 1. 折叠与传感器输入（先只读、默认关闭）

先做 GPIO62/Hall 和 hinge 输入的只读观测路径，输出带单调时钟时间戳的原始状态、去抖后的状态及错误/跳过原因；首版不驱动显示、不发布伪造传感器数据。Host 回放覆盖 active-low、重复边沿、抖动、读失败、资源不匹配和超时。

之后按设备逐项接入 LSM6DSO、AK0991X、TCS3720 和 proximity。每类设备分别核对 DT、上电/复位、总线、IRQ、标度、单位、采样时间和 iPadOS 消费接口；一个设备一次，不以 Android 枚举代替 iPadOS 数据验收。

验收：主机测试与 reduced/full kernel 构建通过；隔离启动后看到实际硬件事件及时间戳，服务/API 读到与原始输入一致的数据。传感器观察通过前，屏幕路由保持不变。

### 2. GNSS 原生位置链

先只读盘点 zizhan GNSS 控制器、固件和电源/时钟依赖，以及 22H374 的定位服务/provider 装载接口。随后实现真实 provider 到系统位置服务的最小链路；权限由系统原生界面管理，不能返回固定坐标、模拟卫星、伪造 HAL 成功或把网络天气数据当定位结果。

验收：真实前台应用触发活动请求；记录 provider start、GNSS session、卫星、TTFF、定位时间和精度，并确认真实坐标送达原生位置 API。无 fix 时记录实际 HAL/固件错误并停止依赖它的后续工作，不用无请求状态判硬件失败。

限制：首次有效定位需解锁并在室外或无遮挡位置保持前台请求；主机任务可无人值守准备，现场 fix 不能由自动化伪造或保证。

### 3. CS35L41 输出与输入

按 SE15 与两颗 CS35L41 的真实板级资源建立独立 zizhan 路径；不修改现有 TFA9873 profile。顺序为：资源和电源前置核对、只读 chip-ID、codec/调音与固件依赖、ADSP/TDM 路由、低音量短 PCM 输出、静音/停止/重复启动恢复。麦克风 capture 另行确认硬件、ADSP 通道和用户态 ABI，不先暴露空输入端点。

验收：host I2C/protocol 和资源负控制通过；设备日志证明合法身份、路由建立和停止恢复；现场听测确认目标扬声器、音量变化、无持续噪声/异常。未完成前 `pong_audio=0`，只读 probe 不写 OTP/MTP，不套用其他芯片调音。

### 4. 外屏静态显示、触控，再做自动切换

依赖 DSI1/PHY1、secondary L18 的供电/reset/PPS/DCS、独立 TE/frame 观察和独立资源 owner。先固定折叠姿态做外屏静态测试图与帧推进；随后单独接 SE19 触控并验坐标方向/边缘。只有两路显示都稳定后，才实现排空旧帧、切换显示与触控 owner、等待新屏首帧/TE、超时回到原屏的手动切换事务。最后才把经实机确认的 Hall/fold 事件接入带去抖的自动切换。

验收：外屏有真实可见图像和持续帧推进；SE19 输入方向正确；两次完整开合的事件、显示状态、触控 owner 和首帧时间线相关；失败注入可回到原屏。自动切换前必须有人观察真实出光并可物理恢复。

## 无人值守范围与设备门槛

可无人值守推进：源码/DT/ABI 审计、host parser/protocol/replay 测试、default-off 实现、daily/reduced/full host 检查、reduced/full kernel 构建、隔离候选打包和完整身份/回退 preflight。

每次设备轮次只启用一个变量和一个 owner；后部 USB-A、临时 `fastboot boot`、现有自动返回与 Android witness、pinned klog、30 分钟单轮上限继续保留。温度只记录；温度或运行时间可能影响日志时单独降级证据完整性。不得刷分区、离线改 Data/TCC、覆盖负结果或依赖旧 epoch/旧候选身份。

必须有人在场的边界：第一次实际功放输出/听测、首次外屏点亮/触控、自动折叠切换及任何需要解锁/选择系统权限的 GNSS 现场请求。到这些边界时，无人值守任务应停止在已准备且默认关闭的候选，并报告需要的现场动作；不得自行打开输出、切屏或伪造用户授权。
