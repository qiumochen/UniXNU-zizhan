# 20小时无人值守计划（2026-11-17）

状态：仅规划，未启动。T0由用户确认；未创建心跳、未派设备轮、未安装或构建。基线是`034a0b0037b28f4ff4e46703cbd4d9bb75db25e5`加现有未提交工作树；最后已知安装为原weather UI，本轮计划开始前必须重新核对，不把最后已知状态当当前状态。当前队列与边界以[STATUS](../progress/STATUS.md)为准。

## 目标

在不需要用户在现场的条件下，把音频主线从“主机有限批次核心”推进到：

1. 单图`WR_SHMEM 48k/2ch/24bps → MFC 0x07001015 → TDM sink 0x0700100e`的默认关闭主机计划、负控制、双内核与候选包；
2. 至多五轮音频静音资格：A图生命周期与真实MAP句柄、B 480帧有限零数据、C可选的480帧已知非零测试数据、D默认关闭运行时入口、E可选的停止/超时/欠载；AMP/BST/TX始终关闭；
3. 默认关闭运行时入口与真实HAL环生产者的主机接线，不发布Ready、不启动系统音频设备；
4. 一次独立的UI-STATUS-03收口：电池右上布局与设置页完整画面，通过则保留工作UI，失败则恢复原weather UI并完整读回；
5. 传感器只做25分钟解阻判断；没有可信六票来源就保持BLOCKED，不重复采表、不写资源、不启动remote3/SLPI。

20小时是预算，不是完成承诺。若音频单图在第一个设备轮被DSP拒绝，立即停止该设备路径，转向主机/HAL/UI；不靠猜模块、端口或格式继续烧轮次。

关键路径是`P1单图主机 → A图生命周期 → B有限零数据 → P4默认关闭运行时 → D有限数据`；UI-STATUS-03独立于音频，音频失败也必须完成UI收口；传感器只有25分钟判断位，不占关键路径。

## 总体执行规则

- 一次只有一个手机owner；同一时间只跑一个设备轮、一个安装或一个写操作。主机构建可以在不碰手机时独立进行。
- 每个设备轮：15分钟fresh preflight、30分钟监督上限、自动/panic/电源键返回、后部USB-A、临时`fastboot boot`、新鲜pinned日志、Android完成见证；结束后15分钟严格review。
- 心跳/监督器是唯一长运行进程；任何后台cycle/build必须有可查询receipt、PID和日志，不留下无监督的detached进程。
- 每个设备轮只改变一个变量，记录假设、控制、源码/内核/镜像/UI/helper身份、boot args、接受条件、回退和日志位置。
- 最多6个设备轮：A图生命周期、B有限零数据、C可选非零测试数据、D默认关闭运行时owner、E可选停止/超时/欠载、F UI安装/验证。任一轮失败即保留负结果，不用同输入重跑。
- 时间表是预算，不是硬承诺：主机阶段可以顺延，但设备轮不得压缩fresh preflight或30分钟监督；T+16:00后不新OS写、T+18:00后不启设备轮、T+20:00收尾保持不变。
- 每个主机批次后：针对性host测试、完整日用host（受影响时）、精简与完整内核；记录source hash、kernel hash和包身份。
- 设备异常（NO_FASTBOOT、未返回、panic、fatal、功放fault、温度异常）立即停止后续轮次，先协调实际设备/镜像状态，再决定是否转主机任务。

## 各阶段最小交付

### P1 音频单图主机

- 用公开SPF/AGM结构编码单图：`WR_SH_MEM(0x07001000) → MFC(0x07001015) → TDM sink(0x0700100e)`；客户端拥有SG/容器/端口/实例ID，TDM硬件参数来自已核ACDB，MFC输入48k/2ch/24-bit packed、输出96k/3ch/24-bit。
- 允许一个owner下必要的subgraph/container，但必须同一生命周期、同一变量；不回到分离PCM/TDM图的重启/停止顺序。若DSP拒绝24-bit packed输入，保留status/reason并停止，不改未证实的32-bit/float参数强行重试。
- 负控制至少覆盖：缺MFC、错模块/端口、错误media format、重复/缺失连接、错token/peer/status、超时、错误DONE、无真实MAP句柄；拒绝时保留opened/uncertain，不伪造Ready。
- 主机入口默认关闭，例如独立`zizhan_audio_graph=1`；不设`pong_audio`、不启旧TFA路径、不启PRM34/attended1。
- 通过针对性ASan/UBSan、完整日用host、精简/完整kernel；记录source hash、kernel hash、包身份和回退。

### P2 设备轮A

- 只验证图构造/生命周期与真实映射；不发送PCM数据、不接GPIO124、不启AMP/BST/TX/ASP输出。
- 如果DSP在START前要求MAP/handle，复用已验的UEFI extent/SMMU/lease路径；句柄不是实测非零就停止，不用假句柄推进。
- 接受条件：图各命令真实ACK/status0、映射句柄非零、stop/close/cleanup顺序完整、无panic/fatal/audio、新鲜deadline日志、Android完成。
- 失败即保留原始命令/status/reason，停止音频设备路径；不猜随机ID、不重派同输入。

### P3 设备轮B/C

- B：从真实映射的48k/2ch/24-bit packed缓冲区取4×480帧（每槽2880B），实际WRITE/真实V2DONE；确认地址、handle、token、status、metadata和1920帧累计；输出关闭，完成后清零/UNMAP/释放/cleanup。
- C仅在B通过且存在独立目的时执行：固定低幅度已知测试数据，验证MFC对非零输入的消费和DONE；不打开功放，不称声音。
- 任一轮出现错token/迟到/重复DONE/超时，保留uncertain和映射，不用清零或下一次WRITE覆盖未知内存。

### P4 默认关闭运行时主机

- 把单图计划接入默认关闭的运行时入口：HAL环取数、24-bit打包、480帧批次、欠载门控、停止/超时/错误保留。

- 增加主机负控制：无生产水位不发、环帧不足不填零、错误格式拒绝、重复/迟到DONE、在途停止、资源保留。

### P5 设备轮D/E
