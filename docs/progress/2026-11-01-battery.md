# zizhan 电池（ADSP 电池管理）接入 — 2026-11-01

## 结论
ADSP（音频 DSP，高通的电池/充电管理在它上面跑）在 iOS 内核下成功启动，经 PMIC GLINK 读到电池，`PongBattery`（IOPMPowerSource）已发布给 iOS。
g206 读数与安卓 sysfs 一致：电量 100 %、4444 mV、充电 426 mA、34.40 °C、满充 3507 mAh / 设计 4500 mAh、循环 907 次、USB 在线、正在充电。
**还没人眼确认**：状态栏电池图标、设置 › 电池、拔插充电器的变化 → 第 6 节。

## 1. 起点
- 代码早已在树里：`drivers/PongPower`（从 UniXNU-pong（Nothing Phone 2，同为 SM8475）移植；ADSP PAS1 启动、SMEM/SMP2P/GLINK、`ShengBattmgr` 协议、`PongBattery`）。
- zizhan 一直关着：`ci_boot_ufs.sh` 写死 `pong_adsp=0`（"zizhan hardware differs from Pong"）；而且 PongPower 只在 `CONFIG_XNU_PONG_WIFI=y` 时才链接。
- 参考：UniXNU-sheng（小米 SM8550）`package/ShengBattmgr.c`、`porting.toml` power 节（"Battery properties after 11 are shifted by one"）。

## 2. 与 Pong 的硬件差异（安卓 live DT：`/sys/firmware/fdt` → `device/dts/zizhan-live-android.dts`）
| | Pong | zizhan |
|---|---|---|
| ADSP carveout（adsp_region） | 0x85700000 + 0x2800000 | **0x9fd00000 + 0x3100000** |
| SMEM / TCSR mutex / IPCC / AOSS / RSC DRV2 / cmd-db | 0x80900000 / 0x1f43000 / 0xed18000 / 0xc300000 / 0x17a20000 / 0x80860000 | 相同 |
| 固件 | adsp.mbn | `/vendor/firmware_mnt/image/adsp.mdt + b00..b25`（modem 分区 FAT），合并后 22.8 MB，加载跨度正好 0x3100000 |
| 电池属性编号 | QTI 标准 | 小米：12 起后移一位（温度 13、电荷计数 15、循环 16、设计 17、满充 18、充满时间 20、放完时间 21）；温度单位已是 0.01 °C |

## 3. 改动（UniXNU-zizhan，镜像在 device/）
- `drivers/PongPower/PongAdsp.cpp`：carveout 改为 zizhan 值；survey 结果打一行 IOLog。
- `drivers/PongPower/PongPower.cpp`：`pong_adsp=1` 真正只做映射 + 调查（之前 1 不进入）；2 才启动 DSP 与电池。
- `drivers/PongPower/ShengBattmgr.c`：小米属性编号；温度不再 ×10。
- `drivers/PongPower/PongBattery.cpp`：每次刷新打一行读数（电量、mV、mA、温度、标志、USB、满充、设计、循环）。
- `drivers/PongPower/PongRpmh.cpp`（新）：不编 WiFi 时提供共享 RPMh 投票（APSS DRV2 active TCS4）与 SMMU 租约锁，代码取自 PongWifiPlatform.cpp。
- `scripts/build-pong-power-native.py`：没有 Pong 的 tfa98xx.cnt 时生成空功放表（zizhan 不开音频）；无 WiFi 时把 PongRpmh.cpp 与 sheng `QcomRpmh.c` 编进来。
- `CONFIG_XNU_PONG_POWER`（`configs/zizhan_ipados18_gpu_defconfig` = y）：`build-xnu-ipados18.sh` 三处条件、`build-pong-platform-macos.py` 的 `-DXNU_PONG_POWER`、`ArmDTPlatform.cpp` 调用 `pong_power_start_optional`，均与 WiFi 解耦。
- `src.noindex/ci_boot_ufs.sh`：`pong_adsp=${ADSP:-0}`（环境变量 ADSP=1/2 打开；boot-arg 先到先得）。
- 固件：`tools/mac/mdt2mbn.py`（mdt + bNN → mbn）、`tools/mac/fw-refresh.sh TAG MBN`（放进 OS 镜像 `/pong/firmware/adsp.mbn`，部署同 ui-refresh）。已部署 `fw-refresh.sh g204`。固件不进 git。

## 8. 设置 › 电池卡死：根因链（g208–g216）
无人值守复现：`pong_url=15`（SpringBoard 15 s 后打开 `prefs:root=BATTERY_USAGE`）+ 合成点按触发 gs 采样。新增内核选项 `gs_all=2`（0005：等待中的线程也记录，前 12 个），`tools/mac/gsym.py LOG GESTURE [TID..] --bin BIN`（整条栈符号化；自带二进制用 atos，从 OS 镜像拷到 Mac `work-sym/`）。

| 轮 | 采样进程 | 主线程/关键线程卡在 |
|---|---|---|
| g208 | Preferences | 1000/1000 W：`-[PowerUISmartChargeClient isMCLSupported]` → NSXPC 同步 → PowerUIAgent |
| g210 | PowerUIAgent | 主线程 `-[PowerUISmartChargeManager isExternalConnected]` → `-[_CDClientContext objectForContextualKeyPath:]` 同步 → contextstored |
| g211 | contextstored | 主线程启动没走完：`CDMonitorManager init` → `_DKMotionMonitor init` → `+[CMMotionUtils featureAvailability:]` → CLConnection 同步 → locationd |
| g212 | locationd | 内部 silo 串行队列被 tid 898 占着：混淆代码里的 MIG 1203 同步请求（字符串逐字节 −0x5a），其余线程排队 |
| g214 | locationd（去掉 fairplayd 后） | 898 消失、主线程回到 run loop；silo 仍被 `TMGetRTCResetCount`（同步问 timed）占着 |
| g215 | timed | tid 857 卡在内核 **`gethostuuid()`** |

**根因**：`gethostuuid()` → `IOBSDGetPlatformUUID` 等 `IOPlatformUUID` 资源，超时 0 = 永远等。arm 上 `IOPlatformExpertDevice::generatePlatformUUID` 只用 `/chosen` 的 `unique-chip-id`(8 B) + `chip-id`(4 B) 生成；我们的 ADT 两个都没有（make-pong-adt-ipados18.py 支持，但 build-ipados18-bootimg-local.py 没传），所以内核从不发布 UUID，所有调用 gethostuuid 的进程永久阻塞。链条：timed → locationd → contextstored → PowerUIAgent → 设置 › 电池。locationd 卡死也意味着定位/运动相关全都不可用（传感器方向要用）。

**修复**
1. build-ipados18-bootimg-local.py 传 `--unique-chip-id b0f5da20 --chip-id 8010`（软件种子：本机 fastboot 序列号 / iPad7,11 的 A10；注释说明不是 Apple 硬件标识）。
2. fairplayd.A2：在本移植上一启动就 exit(0)，KeepAlive 每 10 s 重启，launchd 握着端口，排队请求永远没人回。build-ipados18.py 新增 `EXCLUDED18` 把它排除出服务缓存；`tools/mac/jobs-refresh.sh TAG LABEL…` 对现有镜像生效（g213 已装）。待 UUID 修好后再试一次放回 fairplayd，看它是否只是因为拿不到 UUID 才退出（备份：prepared/pong-ipados18-system.g213.cdr 是改之前的镜像）。

**11-02 补记**：09:28 为调查 ASTC 开启后的 Weather 卡住，从保留的 g213 修改前镜像把 fairplayd.A2 job 和 plist 回填到当前已安装 OS 镜像。g245 不再有 fairplayd failed lookup，但 launchd 仍反复重启该服务，功能与因果关系尚待验证；`EXCLUDED18` 仍排除它，全量重建会再次移除。见 [ASTC / fairplayd 交接记录](2026-11-02-gpu-astc-and-fairplayd.md)。

**状态**：g216（UUID 修复后的验证轮）开跑时手机在 `adb reboot bootloader` 后从 USB 上消失，10 次 VBUS 断电 + 一次 12 s 断电都没回来（uhubctl：端口有电、无设备），需要人手插拔线/按电源键。Mac 上 `when-back.sh g216 …` 在等手机重新出现，出现后自动跑完验证。

工具：`tools/mac/cycle-resume.sh`（round 被中途停掉后收日志）、`tools/mac/when-back.sh RUN ARGS…`。

## 9. UUID 修好之后：SBRendererService 被杀时内核 panic（g216–g220）
- UUID 种子加上后，整条链通了，Preferences 主线程不再卡在 isMCLSupported（g218：主线程在跑 SwiftUI 布局）。
- 但 g216/g217/g219 内核 panic：`pmap_assert_free: Found at least one mapping … is a User CPU mapping`。干净 klog（g219）的栈：SBRendererService 超出内存 ledger 被杀 → `iokit_no_senders` → `AGXDeviceUserClient::clientClose` → `NativeAdrenoUserClient::releaseAll` → `freeBo` → `NativeAdrenoMemory::release` → `IOBufferMemoryDescriptor::free` → VM 释放页时发现还有用户 PTE。以前电池页根本走不到渲染图表这一步，所以没触发。
- 修复：
  1. `PongAdrenoClient.cpp` dropViews：`removeMappingForDescriptor` 返回的 map 以前被丢弃（泄漏且不 unmap），改为 `unmap()` + `release()`（AGXDeviceUserClient 早已这样做）。
  2. 兜底：`NativeAdrenoDisconnectPages()`（NativeAdrenoCpu.cpp），`NativeAdrenoMemory::release()` 在自有页还给 VM 之前对每页 `pmap_disconnect`，不管哪个 pmap 还映射着都清掉；计数 `native_adreno_disconnect_stats[0]` BO 数、`[1]` 页数。
- g220（两处修复后）无 panic；只是 ramoops 副本（从 fastboot 开跑，klog 没武装），证据弱。v9 用户轮验证。
- 另：今晚 `adb reboot bootloader` 后手机经常不在 USB 上出现（g213/g215/g216/g217/g220），usbkick 多踢几次或 when-back.sh 等它回来。

## 10. 电池页内容：健康度转圈、图表空白（v10–g228）
- v10（用户）：电池页能打开、不卡不崩；健康度一直转圈、没图表。

- 改动：PongBattery 类改名 `AppleSmartBattery`（IOLog 前缀仍是 "PongBattery:"），加 `Serial`（ZIZHAN-BM4V）、`BatteryData`{DesignCapacity, CycleCount, NominalChargeCapacity, StateOfCharge, Voltage}、`MaximumCapacityPercent`。v11（用户）：仍转圈、无图表。
