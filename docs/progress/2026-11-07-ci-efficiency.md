# CI 触发策略与效率调整（2026-11-07）

## 原因与范围

用户要求减少日常提交的重复云端构建：内核 / 驱动开发已有本机精简和完整设备配置验证，云端应保留快速独立检查与按需干净环境构建。

入口源码为 `477417e2d8daf9efbb74e78dc98f40a55f8fbe96`。本次仅修改工作流触发条件与说明，不改变编译命令、驱动、内核、镜像、手机安装态或硬件资格。入口已有的功能清单文档变更属于另项工作。

## 生效后的规则

| 事件 / 改动 | 自动运行 |
| --- | --- |
| 只改 Markdown 文档 | `Porting record` |
| 显示驱动、截图 / 帧时序工具或相关测试 | 记录检查与显示回归；共享电源或 UI 源码同时触发日用回归 |
| Wi-Fi 驱动、地址服务、USB 失败路径工具或相关测试 | 记录检查与 Wi-Fi 回归；共享用户态代码同时触发日用回归 |
| 温度、电源、启动偏好、用户态服务策略或相关测试 | 记录检查与日用回归；共享显示电源或 UI 源码同时触发显示回归 |
| 公共配置、设备树、格式 2 层、源码固定版本、`scripts/`、XNU 补丁或公共 action | 记录检查与三组主机回归 |
| 修改某组主机回归工作流 | 记录检查与该组回归 |
| 手动启动 macOS 工作流，`task=kernel` | 只运行内核 job |
| 手动启动 macOS 工作流，`task=disk-probe` | 只运行磁盘 / 工具诊断 job |

三个快速工作流保留 push、PR 和手动入口，push / PR 使用相同路径列表。没有给记录检查添加路径过滤。子系统路径覆盖测试入口、实际读取的源码和本地工具；公共构建与配置路径保守地运行三组。

macOS 工作流取消 push 入口，保持原有固件和 IPSW 输入、构建命令、超时及产物处理。新增必选 `task`，默认 `kernel`。两个 job 按选择互斥，concurrency 按 ref 和 task 区分，手动磁盘诊断不会取消同 ref 的手动内核构建。需要的内核 job 自身磁盘准备步骤保留。

## 操作与验证边界

本机内核 / 驱动改动仍需同时构建 `pong_ipados18_ci_defconfig` 和 `zizhan_ipados18_gpu_defconfig`，并跑受影响的主机回归。阶段性发布、工具链 / 构建脚本变动或重建性调查时手动运行云端内核；环境排障单独运行磁盘诊断。云端工作流只跟踪实际触发的精确 SHA，未运行项不记 PASS。

```bash
gh workflow run macos-build.yml -f task=kernel
gh workflow run macos-build.yml -f task=disk-probe
```

路径过滤跳过的工作流不会产生成功检查，不能将这些可选、按路径触发的回归或手动 macOS job 设为所有 PR 都必须出现的检查。分支合并门禁若需要始终存在的检查，应使用无路径过滤的记录检查。路径过滤不负责发现未来新增加的依赖；新增测试或依赖时同步维护对应工作流。
