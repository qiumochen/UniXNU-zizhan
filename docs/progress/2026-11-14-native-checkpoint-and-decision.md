## 当前到底卡在哪里

**发布检查点为 544 个正式准入未闭合目标，研究图还缺 458 个。** 这是 `zizhan-imported-data-closure-v4` 完成结果，caller/imported-data 迭代已到固定点；558/464 等数字是前一批历史。现有 caller 证书确认 213 项 API 和 14 项数据身份；另有独立 typed allocator、stack guard 和 KDK 完整操作数证据。

最新 typed-caller 调用边界 v2 主机扫描已经结束，输出 227 项 API/14 项数据及负控制。它尚未合并到上述闭包；不能因为扫描发现更多候选就改写正式缺口。后续须先核对与已有证据的兼容，再做一次新闭包。这次发布不为追逐更小数字重开长研究。

原版 Pong full 和 zizhan full 在相同公开工具、Apple 输入、27 个保留组件下分别缺 639/640 项，639 项共同。因此主要瓶颈是共享的原厂 API 地址身份恢复，不能理解为小米新增了几百个硬件故障。上游迁移记录提到 services174 的 113→0 人工复核，但完整 reviewed map 与生成材料未随当前公开配方提供。也不能据此断言所有剩余项只有取得私有表才能解决；caller 原始导入恢复已经产生可重算的新证据。

两次诊断证明“内核已经执行”，不证明完整设备接线。source-only full 中存在指向未映射 retained 父类的静态依赖；第二轮可辨 LR 与 `OSMetaClass::postModLoad` 相符。ramoops 有位翻转，不宣称精确 FAR/PC。继续启动相同不完整内核没有推进价值。下一次有意义的设备试验必须基于真实 retained 组件集合，或有明确新假设的隔离候选。

## 后续工作量和难度

下面是单人持续投入的工程估算，**不是承诺、实测工期或按缺口线性外推**。人日指有效研发投入，下载/排队/编译另有日历等待；主要不确定性在第一项和第一次完整启动后的未知故障。

| 阶段与验收交付 | 主要工作 | 难度 | 粗估剩余投入 |
| --- | --- | --- | --- |
| 导入身份闭合 | 合并已完成 typed-caller 边界证据；按真实 API/data 分组处理剩余项，保留错 API/调用位置/对象布局负控制 | 很高，反汇编与 ABI 证据工程；有长尾 | 3–10 人日；若关键数据身份或上游材料缺失，可能数周以上 |
| 完整集合主机验收 | 实际发射 fileset，覆盖 retained imports、重定位、PAC、类布局、4KiB 几何；按完整组件重新算 typed-zone 预算 | 高；工具已有基础，零名字缺口仍不等于通过 | 身份闭合后约 1–3 人日，发现 ABI 冲突另计 |
| 首次完整桌面 | 实际 loader→C++/IOKit→UFS/APFS→launchd→SpringBoard→可见桌面；独立 OS/Data 和有界返回 | 很高，硬件与用户态交叉，未知故障最多 | 主机验收后约 2–7 人日；可能更长 |
| 恢复旧路线基本功能覆盖 | 触控、GPU 图形正确性、Wi-Fi、亮度、电池、应用及重复返回；回归并比较旧路线 | 高；早期启动不覆盖这些 | 桌面后约 1–3 周；不含音频/蜂窝/睡眠等新增完整能力 |

因此目前没有依据承诺“今天必进桌面”，也没有可靠的剩余百分比。544 不是 544 项等量小修，可能一份有效身份种子解决一批，也可能一个对象布局问题阻塞多天。研究图的 197 或所谓“约 140 个完全未知”只能帮助找线索，不能拿来当可执行剩余量或交付工期。

## 有必要切吗

**短期为了继续用桌面、修天气/网络/电源，迁移不是必需前置。建议保留旧路线作为默认，把新路线作为明确里程碑的特性分支。**

新路线值得保留的理由是：跟随 Pong 后续原生工程、共享现代 arm64e/PAC 和组件 ABI 的适配经验，并为未来仅在此路线提供的修复/组件留通道。这是维护方向与技术能力的投资。它不自动带来更快 GPU、更省电、可用蜂窝、音频或相机；目前没有本机对照证据证明这些收益，不能用于论证必须立刻切换。

本机面板/触控/电源/温控/音频/Wi-Fi 的很多修复可以在旧路线独立推进；能否回移要按具体补丁的 ABI 和依赖判断。Pong 同 SoC 值得持续借鉴，但硬件参数和已验证功能不会随 fork 自动继承。

建议用三个门槛决定是否继续扩大投入：先拿到可重算的零未闭合完整集合；再拿到带新系统身份的真实桌面和可靠返回；最后达到旧路线关键功能覆盖并测得至少一项具体收益，再讨论默认切换。若一个约 3–5 人日的后续阶段没有产生新的可靠身份闭合或具体集合交付，应复审证据方法、获取上游复现材料或回到旧路线功能开发，避免无边界堆参考内核。
