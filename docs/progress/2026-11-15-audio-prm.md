# 音频DSP控制通道与数字核心资源租约

源码基点 `034a0b0037b28f4ff4e46703cbd4d9bb75db25e5` 加未提交修改。接续[用户播放时的实际格式与DSP进展](2026-11-15-audio-clock-route.md)，本批AUDIO-PRM-01最小交付为真实APM readiness、数字音频核心资源请求及独立释放ACK。物理位时钟/引脚、TDM graph、功放和播放资格不在本批范围，当前队列见[STATUS](STATUS.md)。

## 来源与有限事务

本机原machine模块的MI2S/TDM资源路径调用digital codec核心投票；原PRM模块的60字节核心请求/释放结构与维护中的GPR/AudioReach编码核对。公开固定[Linux v6.6 q6prm.c](https://github.com/torvalds/linux/blob/v6.6/sound/soc/qcom/qdsp6/q6prm.c)也给出同一命令/参数与completion协议。只使用已核对的block2，不猜时钟频率或物理槽宽。原机文件及反汇编留仓外。

`zizhan_audio_prm=1` 才在ADSP初始化后注册独占的`adsp_apps`客户端，端口2101；要求确切zizhan board、pong_adsp2、pong_audio0且无SE15 prepare模式。默认不分配/注册/启动线程。此候选不与PongAudio/TFA路径共用owner；不访问codec、pin、DMA或音频服务。

单次APM readiness query，实际ready1后请求digital core block2，独立PRM completion成功后只释放本轮自己的租约，并等待独立release completion。每步唯一token，无重试；strict检查domain、src/dst port、token、opcode、包长度和payload。Basic ACK不等于PRM completion。返回支持固定源码的status-only和`{request_opcode,status}`两种形状，未知前缀/大小失败，不把任意status位置当成功。

单命令2秒、控制阶段总8秒、等待连接/worker总40秒及4000次固定迭代，冻结时钟也终结。16包有界队列，回调只复制/更新；channel关闭或溢出失败。缺请求ACK或释放ACK时保留不确定/持有状态，终止后不重发或把旧租约给下一消费者，由本轮自动返回/平台复位收尾。静态owner保持直到回调不再可达，避免释放后的访问。

## 后续无声心跳的准确输入与接续要求

这段仅为原机输入核对，不是新硬件写入或心跳结果。原机CS35L41模块的64项PLL频率表中，12.288MHz准确配置为`33`，对应`PLL_CLK_CTRL(2c04)`的reference字段值`660`、mask`7e0`。原机函数顺序为open-loop、reference字段、disable PLL、设置SCLK源0、close-loop、enable PLL，逐项mask保留其他位。原mode19只有默认PLL10，除了没有已建立的外部SCLK，还没有按准确频率表配置；原无心跳不能仅归因于外部时钟。

已保存本机DT明确SCK121为`mi2s2_sck`、6mA、bias-disable/output-high；cape固定源的该组function index1/mux shift2/OE9与本机基址一致。WS123和data122/124分别列出，不能从Pong MI2S SD0方案推定本机播放通路。后续先只连接SCK来验证PLL/保护程序，无需在心跳阶段连接PCM数据；仍须实际clock lease成功、单owner协调SE15和共享reset、GLOBAL/AMP/BST输出关闭回读、准确PLL设置与全部时限。停止顺序必须先停HALO并重新assert共享reset、恢复本轮clock pin，再释放本轮时钟/核心；任何未知写入/释放保留证据并由自动返回复位。当前没有这样的组合执行器，不能并发开启两个原本互斥的probe来代替所有权交接。首声阶段仍另行等待用户听测。
