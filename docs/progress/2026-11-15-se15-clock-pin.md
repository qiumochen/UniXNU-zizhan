# SE15 时钟与引脚设置候选

源码基点为 `034a0b0037b28f4ff4e46703cbd4d9bb75db25e5` 加未提交修改。上一轮实际看到clock votes0、GPIO56/57仍为GPIO/pulldown、reset GPIO输入低，见[前置观察](2026-11-15-se15-platform.md)。本批最小交付是默认关闭的wrapper2 S0时钟/引脚设置与有界回读，不启功放、不发I2C。当前队列见[STATUS](STATUS.md)。

## 设置范围

`ZizhanSe15Prepare.cpp`仅接受`zizhan_se15_prepare=1`，要求zizhan板级身份、audio0且观察模式关闭，一次worker。所有写入仅允许GCC vote页与GPIO56/57 config页；reset、GCC gate/core/RCG与SE窗口都只读。进入前检查reset仍为已观察的GPIO输入低；不符合则零写SKIP，避免默默接管已改变的共用复位状态。

`ZizhanSe15Setup.h`依据固定cape-gcc版本[cb7a356ae138e77992ae199eebb86559d825a673](https://github.com/MiCode/Xiaomi_Kernel_OpenSource/blob/cb7a356ae138e77992ae199eebb86559d825a673/drivers/clk/qcom/gcc-waipio.c)的wrapper2 core/core2x/M-AHB/S-AHB/S0，在`0x62010`保留原值并添加bits0..4，不清其他票。分别核对`0x33280/0x3328c`及`0x2e004/0x2e008/0x2e00c`。AHB的HWCG bit1来自匹配表，自动idle gating与未请求clock不同；S0/core没有这个例外。等待最多100ms并附迭代上限。

不写专属RCG/PLL/DFS频率，不假定继承时钟就是某个I2C速率。通过gate检查后才映射SE15只读，读取固件协议、M/S command active、IRQ与RX FIFO状态；非I2C/disabled/busy均停止，不修改pinmux。仅在GENI允许的空闲状态下，GPIO56/57从先前已观察的GPIO/pulldown/2mA，或已匹配的qup15状态，设置为mux1/up/2mA（低10位7），保留高位；输出模式、其他mux或未获APPS所有权的EGPIO均拒绝。

任何发送后的clock或pin回读失败，保留已写状态并结束，不自动重试，不擅自撤销共享clock票。新入口不写GPIO1、不配置GENI timing/FIFO、不清IRQ、不发命令、不调用身份核心或PongAudio/TFA profile。即使总线设置PASS，功放供电、复位释放、I2C身份与声音仍未验证。

## 回归与设备设计

生产setup核心与实际平台入口运行ASan/UBSan通过，覆盖保留原票/高位、超时/冻结时钟、投票及pin回读不匹配、HWCG、protocol/busy、pin所有权，以及14项平台默认关闭/冲突/线程/映射/reset/失败分支。模拟页逐字节检查，只有vote和两个pin config允许变化，reset/SE均不变；不是硬件成功证据。

新运行时代码须通过日用host及精简/完整kernel后，才准备唯一有界设备轮次。假设为新增clock票使SE可访问，且继承I2C firmware空闲时可设置pins；唯一变量是显式prepare开关及其实现，保持ADSP2/audio0/route1和已装OS/UI/helper。验收分别记录clock结果、GENI资格、pin回读/复位未变与整轮返回；若clock失败或协议不符，保留具体FAIL/SKIP并停止，不能把往返PASS当总线成功。不做原样重试。

设备约束保持后部USB-A、temporary boot、fresh全OS/extent/manifest/backup、210/150秒返回与30分钟supervisor、pinned klog和Android witness。无OS/固件安装、Data离线改写、扬声器输出或reset改变。实际source/host/prepared/device结果在本批终态分别记录。
